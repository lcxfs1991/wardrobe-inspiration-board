# 全量重建模式

> 前置：须先完成「首次使用初始化引导」（索引文件 `index.md` 不存在、为空或没有任何用户条目时）与「公共前置：确定当前用户」，确认真实姓名与真实数据目录后才执行本流程。

## 适用与触发

用户要求把衣橱单品或过往穿搭档案推倒重来、只保留本次识别结果时使用。

| 用户原话类型 | 判定 | 处理 |
| --- | --- | --- |
| 重新构建、全量重建、清空重建、推倒重来、旧数据全部清理后重做 | 全量重建 | 按本文件执行，覆盖旧档案 |
| 重新识别、全量重新索引、重扫、再识别一遍 | 重新识别 | 全量视觉问答，结果**追加**，旧记录保留，同一路径以最后一条为准 |
| 只说「重建」「重新整理」「重新弄一下」等语义不明表述 | 待确认 | 按 [补问呈现契约](ask-format.md) 问**一项**，选项为「清空旧记录只保留本次结果」「保留旧记录并追加本次结果」；未取得答复不写入 |

判定不靠推断。用户说出明确的重建语义才进入本模式，不把普通二次索引升级为重建。

## 前置确认

1. 同一姓名可能在多个数据根注册（例如正式档案根与独立测试根各有一份 `index.md`）。必须确认本次重建写入哪个真实目录，不静默使用最近使用用户、不默认取第一个条目。确认方式为一次一问，按 [补问呈现契约](ask-format.md) 列选项，选项只来自索引里真实存在且经核验的目录，最多三条；没有真实候选时只给手动输入，不拿示例路径凑选项。
2. 确认本轮识别范围（单品目录、穿搭目录或具体图片路径），与用户给出的范围逐项一致，不扩大到父目录。

## 执行顺序

1. 列出本轮范围内真实存在的图片路径，并核对目录中的真实图片总数。
2. 读取目标根下 `wardrobe.md` / `outfit.md` 的真实文本，记录**重建前旧记录条数**，该数字必须出现在最终回显里。
3. 备份：把旧档案原样另存为同目录下的 `wardrobe.bak-YYYYMMDD-HHmmss.md` 与 `outfit.bak-YYYYMMDD-HHmmss.md`，时间用运行时真实值。用户明确说「不要备份」时才跳过，并在回显中写明未备份、旧记录不可恢复。
4. 逐张视觉问答：范围为第 1 步的全部真实路径。识别结果必须来自本轮画面，不把旧记录当作识别结果、不复制旧字段值。
5. 一次性写入完整新档案：覆盖目标档案，只含本轮识别结果。所有品类/场景必须一次写全，不允许写完部分类别就中断留成半新半旧。
6. 校验（四项全过才算完成）：
   - 新档案记录条数 = 第 1 步真实路径数；
   - 图片真实路径无重复；
   - 条数与目录实际图片数一致；
   - 档案中旧记录为 0 条、旧值不再出现。
7. 刷新索引文件的「最近使用用户」与「更新时间」；索引条目结构、其他用户条目与 `profile.md` 一律不动。

## 失败与中断

- 任一步骤 `failed` 或 `cancelled`：不得留下半新半旧的档案；旧档备份原地保留，报告未完成与备份真实路径，由用户决定是否重跑，不自动重试覆盖。
- 视觉问答部分失败：如实报告失败的具体路径与缺失条数，不用旧记录补位，不声明重建完成。
- 校验任一项不通过：按未完成处理，报告差异条数，不声称已重建。

## 禁止

- 不删除、不改动任何图片原图。
- 不清空索引文件、不清空 `profile.md`、不清空灵感与采纳记录。
- 重建只对用户确认的这一个数据根生效，不波及同姓名的其他根、其他用户或父目录。
- 不把「重建」当成放宽识别标准的许可：字段仍只来自画面，识别不出留空并说明。
