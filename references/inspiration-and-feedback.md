# 灵感生成与反馈流程

> 前置：须先完成「首次使用初始化引导」（索引文件 `index.md` 不存在、为空或没有任何用户条目时）与「公共前置：确定当前用户」，确认真实姓名与真实数据目录后才执行本流程；引导写入未全部完成时不得开始灵感生成或采纳记录。初始化引导不预建 `profile.md` 以外的档案文件，资料文件缺失时如实报告，不编造个人约束。

## 适用

用户给出场景（旅游、面试、出差等）、目的地、时间，希望获得穿搭灵感；或用户明确表达采纳结果。

## 情景字段与天气约定

- 情景包含场景、目的地、时间、天气或温度区间。
- 天气或温度优先使用用户本轮指令中给出的真实文本，包括用户在会话中自行查到后贴入的结果，或事先保存到 NAS 的资料。
- 用户未给出时，由委托逐条向用户追问，一次只问一项（先问目的地，再问日期，再问天气或温度区间），上一条未取得答复不进入下一条。
- 追问按 [补问呈现契约](ask-format.md) 呈现：目的地与日期各给一行示例（例如「北京」「2026-11-17」），天气或温度给一行示例（例如「晴，5~12℃，早晚凉」）；这三项没有可点候选，不列选项行，也不拿历史记录、往年同期天气或猜测值顶替。
- Skill 不发起联网检索、不检测联网状态、不判断联网是否成功；联网动作由用户在会话中完成，Skill 只消费真实输入。
- 追问后仍未给出天气时，如实说明该字段缺失并继续基于其余真实字段输出，不推测天气。

## 委托顺序

1. 使用 `delegate --target file-agent --instruction '读取索引返回的真实数据目录下 wardrobe.md、outfit.md 与 profile.md 的真实内容，返回三份文件的真实文本与真实路径；文件不存在或读取为空时如实返回，不猜测内容、不改用其他文件、不让已知路径读取依赖知识搜索索引。'`。
2. 只有第 1 步 `completed` 且返回三份真实文本后，才组装整理委托。使用 `delegate --target document-agent --instruction '基于已确认的三份真实资料文本，整理出可用衣物单品清单、过往搭配记录与个人穿衣约束（含性别与出生年月对应的穿衣约束，仅作为内部取舍依据，不在输出中逐项列出），带来源引用；同一真实图片路径出现多条记录时以档案中最后一条为准，不重复计数；只使用资料中真实存在的内容，不补充资料外的趋势、商品或天气信息；资料中某项缺失时如实说明。'`。组装时把三份真实文本逐项写入 instruction。
3. 主专家基于第 2 步返回的真实整理结果与用户本轮情景字段完成搭配取舍与排序。这一步是推理，不强行委托。输出结构固定为：用户基本信息、本次情景（场景、目的地、时间、天气或温度）、最多三种最合适的单品搭配、最多三种过往搭配记录中最合适的真实照片引用。其中「用户基本信息」只回显当前用户姓名与颜色偏好、风格偏好等非敏感偏好概要；性别、出生年月、身高（cm）、体重（kg）、身形、肤色、常驻生活城市与常驻工作城市可作为搭配取舍的内部约束，但不逐项列出，也不写入生成记录。
4. 使用 `delegate --target photo-agent --instruction '基于已确认的 outfit.md 中真实图片路径，返回最多三种与本次情景最匹配的过往搭配照片引用或预览；只使用真实路径，同一路径只返回一次，不编造照片 ID 或路径，不拿相似照片凑数；无可用路径时如实返回空结果。'`。本步骤使用第 1 步已确认的真实路径，不依赖第 3 步的推理结果。组装时把真实路径逐项写入 instruction。
5. 只有第 3 步输出完成，且第 4 步已返回真实结果（含明确的空结果）后，才组装记录委托。使用 `delegate --target file-agent --instruction '把本次灵感生成的真实结果追加写入用户真实数据目录下的 inspiration-log.md，包含记录标识、运行时真实时间、用户指令原文、情景字段、输出的最多三种单品搭配与引用的真实照片路径；不包含个人资料中的性别、出生年月、身高（cm）、体重（kg）、身形、肤色、常驻生活城市与常驻工作城市等敏感字段；只做追加，不覆盖、不删除历史记录；返回写入后的真实记录标识；保存目标由你确认或准备。'`。组装时把本次真实输出内容与真实数据目录逐项写入 instruction。
6. 写入有审批要求；等待审批不算完成。记录标识以写入完成后返回的真实业务值为准，不预先构造。
7. 展示层按展示契约处理：用户要求可视化、要做成网页或需要可单独发送、离线打开的文件时，在记录写入完成后输出一份单一自包含网页文件，图片一律以 base64 内嵌，桌面端与移动端共用同一份，页面只呈现第 3 步的四部分结果，不展示衣橱全量单品图册与过往穿搭全量图册；宿主不具备生成网页能力时只输出 Markdown 清单并如实说明。展示层不改写任何档案，也不把原图缩放、移动或删除。

## 采纳反馈

- 用户明确说出「采纳第 N 套」或「都不采纳」时，才记录采纳结果；没有明确表达时不写入、不猜测。
- 使用 `delegate --target file-agent --instruction '读取用户真实数据目录下 inspiration-log.md 的真实最后一条生成记录，把用户本轮明确表达的采纳序号或都不采纳以及用户原话追加到该记录；关联的记录标识必须来自文件真实内容，不依赖上下文记忆、不猜测标识；只做追加，不覆盖或删除历史记录；保存目标由你确认或准备。'`。
- 记录文件为空或读不到最后一条时向用户询问，不静默新建关联。
- 采纳结果只作为事实记录，不自动推断偏好、不静默改写 profile.md；后续若要做偏好演进，需单独定义规则并再次经用户确认与审批。

## 边界

- 最多三种是硬上限，不足三种时按真实可用数量输出，不凑数。
- Markdown 清单只保证真实引用路径；网页展示层按展示契约把引用图以 base64 内嵌，桌面端与移动端同一份，不使用相对路径或网络地址。
- 展示层只含本次推荐结果，不搬入衣橱与过往穿搭的全量图册，也不做全量档案规模统计；要看全量档案读 Markdown 档案。
- 输出中的事实只来自真实资料与真实检索结果；不引入未检索到的流行趋势、商品或购买信息。
- 任一必需步骤 `failed`、`cancelled` 或缺少下游必需真实值时停止依赖步骤；部分完成时分别报告已完成、失败或取消、仍在等待、未执行的步骤。
