# 补问呈现契约（选项 / 示例）

## 适用

本文件是**所有向用户补问场景**的唯一呈现标准，各流程文件只补本场景的具体取值，不另立格式。覆盖范围：

- 首次使用初始化引导的 13 项、新增用户、切换用户；
- 多数据根确认、索引模式语义不明确认、范围或照片消歧；
- 个人资料字段缺失时的补问；
- 搭配来源标注、情景字段（目的地、日期、天气或温度）追问；
- 采纳序号确认。

## 两类附属信息

提问条上只允许两种附属信息，两者**不可混用**：

| 类型 | 用在哪 | 能否点选 | 是否直接成为取值 |
| --- | --- | --- | --- |
| 选项 | 有固定词表的字段（肤色、身形），有真实候选的字段（索引里的真实姓名与目录、真实数据根、真实照片目录、第 1 至 3 套采纳序号、来源标注、索引模式二选一） | 能 | 点选即记录 |
| 示例 | 没有词表也没有真实候选的字段（性别、出生年月、城市、颜色偏好、风格偏好、身高、体重、目的地、日期、天气或温度） | 不能 | 不记录；用户自己输入才算答复 |

## 通用模板

```text
第 N 项 / 共 M 项：<字段名>            ← 单项补问时省掉这一行的进度
选项：1) … 2) … 3) …                   ← 有词表或真实候选时用这一行
示例：例如 xxx                          ← 没有候选时用这一行
手动输入：直接回复你的值
```

- 一轮只问一项，一条只问一个字段；不把多个字段并进同一条或同一屏。
- **选项行与示例行互斥**：同一条提问不同时出现，避免把示例当成已选值。
- 有固定词表时**把候选列全**（肤色五项、身形六项，各加「不填写」），不省略、不写成「等」，并附一句释义；释义只作说明，不进档案值。
- 有真实候选时列真实值，最多三条，不拿示例或推测值凑数。
- 示例必须以「例如」开头，只写一条；不预填、不作为默认值、不写入任何档案文件。
- 手动输入入口在每一步都保留；词表或候选之外的说法按原文记录，不改写成最接近的候选。

## 两个实际形态

同一屏只出现其中一种，不并存。

```text
第 12 项 / 共 13 项：肤色
选项：1) 白皙 2) 自然 3) 小麦 4) 蜜色 5) 深色 6) 不填写
     白皙：偏白、偏透亮；自然：不偏白也不偏深；小麦：偏暖、略带日晒感；蜜色：偏深偏暖；深色：深肤色
手动输入：词表里没有你的说法，就直接回复你自己的描述
```

```text
第 10 项 / 共 13 项：身高（cm）
示例：例如「165」
手动输入：直接回复你的数值
```

```text
本次情景：天气或温度
示例：例如「晴，5~12℃，早晚凉」
手动输入：直接贴你查到的天气，或说温度和体感
```

## 各补问点的选项与示例

| 补问点 | 选项（可点，点选即取值） | 示例（不可点，不写入） |

| 初始化 3 是否补充资料 | 现在补充 / 跳过，稍后补充 | 无 |
| 初始化 4 性别 | 无（不列词表，避免从姓名或措辞推断） | 用你自己的说法，例如「女」 |
| 初始化 5 出生年月 | 无 | 例如「1995-03-12」；只记得年份或年月就照原样说 |
| 初始化 6 常驻生活城市 | 无 | 例如「深圳」 |
| 初始化 7 常驻工作城市 | 与生活城市相同 | 例如「上海」 |
| 初始化 8 颜色偏好 | 无 | 例如「黑白灰」「莫兰迪色」 |
| 初始化 9 风格偏好 | 无 | 例如「简约通勤」「法式复古」 |
| 初始化 10 身高（cm） | 无 | 例如「165」 |
| 初始化 11 体重（kg） | 无 | 例如「52」 |
| 初始化 12 肤色 | 白皙 / 自然 / 小麦 / 蜜色 / 深色 / 不填写（列全） | 无 |
| 初始化 13 身形 | 苹果型 / 梨型 / 沙漏型 / 直筒型 / 倒三角型 / 匀称型 / 不填写（列全） | 无 |
| 新增用户、切换用户的数据目录 | 索引里其他真实目录（仅作参照，不静默套用） | 例如 `/Users/<你>/…/wardrobe-<名字>` |

| 情景·日期 | 用户本轮已给出的日期 | 例如「2026-11-17」 |
| 情景·天气或温度 | 无 | 例如「晴，5~12℃，早晚凉」 |
| 照片或范围消歧 | 真实扫描到的目录或场景，最多三条 | 例如 `outfits/travel` |
| 采纳序号 | 第 1 套 / 第 2 套 / 第 3 套 / 都不采纳 | 无 |

## 单条答复的判定

| 这一条的答复 | 判定 | 下一步 |
| --- | --- | --- |
| 点选了选项，或自己输入了具体值（含照着示例写法打一遍） | 记录该项真实值 | 进入下一条 |
| 明确说跳过、不填、稍后再补 | 该项保持空缺并如实说明 | 进入下一条 |
| 只点了「手动输入」入口，没有带出具体值 | 视为未答，不当作已记录 | 重问同一项，不进入下一条 |
| 把示例原文复述回来但没有点选项 | 视为用户输入，按该值记录 | 进入下一条 |
| 说「剩余都跳过」「先到这里」 | 已答项保留，其余空缺 | 结束提问，进入写入或输出 |
| 取消 | 停止该补问 | 不发起依赖该值的写入或输出 |

同一项重问一次后仍未取得值：必填项（姓名、数据根目录、范围）停止并说明缺哪一项；可选项按空缺继续，不反复追问。

## 呈现降级

- 宿主支持可点选项或底部动作面板（ActionSheet）时，按本契约一项一屏逐条弹出。
- 宿主不支持时，输出同一份内容并降级为「当前这一项的编号选项 + 一行手动输入提示」，不退化成说明文字墙，也不把后续字段一起列出来。
- 控件形态不改变字段集合、跳过语义、敏感字段边界与完成判据；是否弹出由宿主决定，等待答复期间按 `waiting_user` 处理。

## 边界

- 选项只来自真实值或本 Skill 固定的肤色、身形词表；示例不是候选，不能拿来当选项渲染、不能预填、不能补写成取值。
- 敏感字段（性别、出生年月、身高、体重、肤色、身形、常驻城市）只在资料文件内使用；补问条里不展示这些字段的已记录值，只报已记录项数与空缺项数。
- 天气或温度不由 Skill 检索，只消费用户给出的真实文本；缺失时如实说明并继续，不推测。
- 父层不硬编码控件名称、不承诺控件一定渲染、不调用 CLI、不构造等待信封。
